# 操作方法

[English](controls.md) · [画面と検証記録](draw-ui.md)

初期状態はDRAW、位置(7,7)、北向き、PEN DOWN、normalized前処理です。

| 操作 | DRAWでの動作 |
|---|---|
| ボタンを離して回転 | 方向を45度ずつ変更 |
| 短押し | 1マス前進 |
| 押しながら正／負方向へ回転 | 向きを変えず前進／後退 |
| 回転せず700ms長押し | MENUを開く／閉じる |

デコーダーはMopping_rotalyと同じ2エッジ設定です。物理的な回転方向・1クリックあたりの
イベント数は配線とエンコーダーに依存し、実機確認が必要です。PEN DOWNは移動経路を描き、
PEN UPはカーソルだけを移動します。端では座標を固定し、反対側へ回り込みません。
短押し1回、または押下から解放までの連続移動が、それぞれ1回のUNDO単位です。
左右の回転を合算して打ち消さず、取得した順番に処理します。

押下回転後は、解放時の短押しと長押しMENUを発火させません。長押しでMENUが開いた後の
同じ押下中の回転はメニュー選択として扱い、描画しません。20msのデバウンス中と安定状態への
切替時の回転は破棄し、途中までの位相もリセットして誤分類を防ぎます。

MENUはRESUME、PEN UP/DOWN、UNDO、PREDICT、CLEAR、SAMPLE、INSPECTを維持します。
選択行は白黒反転し、PEN項目には切替後の動作を表示します。長押しで閉じる場合は、元の
モード・画像・判定結果を保持します。RESUME選択は明示的にDRAWへ戻ります。
CLEARは従来どおり確認画面なしで消去します。

左は16×16のBitmapを3倍にした48×48画素の領域です。四角いカーソルと8方向の矢印は
表示専用で、推論入力へ混入しません。端に向かう矢印はカーソル位置で矢尻が終わる形にして
方向を示します。塗りつぶし／輪郭の丸でPEN DOWN／UPを表示します。
右側は判定専用です。空白は`--`、推論待ちは3点、完了後は5×7字形を20×28画素へ拡大した数字です。

Bitmapの画素が変わった場合だけ判定を無効化します。方向変更、ペン切替、PEN UP移動、
端での停止、既存の線のなぞり直しでは再推論しません。最後の画像変更から600ms経過し、
押下回転の操作が終わった後に自動推論します。PREDICTによる明示的な推論も維持しています。
SAMPLEは従来の2件（元の検証データの0番と7番）を使い、回転で切替、短押しでINSPECTです。
INSPECTは回転で出力を選び、短押しで保持した描画へ戻ります。PASSは全Logitの参照一致であり、
正解ラベルとの一致率ではありません。LogitやMarginは確率ではありません。
`-Dtrace=true`では実際のHidden Activationを表示します。ホスト画像に架空の実機時間は表示しません。

## 入力取得と制限

現在はEXTIではなくGPIOポーリングです。メインループとOLED各ページ転送後の6msの区間で
ボタンとエンコーダーを同時取得します。4件の固定キューに分類済みイベントと32bit取得時刻を保存し、
8ページの描画が終わってからAppへ適用します。追加Framebufferや大きなUndo履歴は使いません。

キュー超過時は未処理イベントを破棄して操作を終了し、metricsの`lost`を増やします。
押下中は解放まで操作を抑制し、非押下時はキューを消費後に復帰します。入力の一部を失う場合は
ありますが、誤った短押し・順序の逆転・推論待ちの永続化を避けます。
I²C転送・描画・推論中の取得間隔や高速回転による取りこぼしは、実機評価待ちです。
